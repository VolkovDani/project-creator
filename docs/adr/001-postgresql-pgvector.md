# ADR-001: PostgreSQL и pgvector для MVP

Статус: принято. PostgreSQL и импорт из SQLite реализованы в #14;
семантический поиск — в #7, анализ требований — в #8.

## Контекст

MVP хранит проекты и бизнес-требования с привязкой к рабочей области. Для RAG
нужен поиск по смыслу; поиск по точным словам и идентификаторам остаётся
направлением развития.
Связь результатов с доступными пользователю проектами и версиями источников
должна сохраняться.

## Решение

PostgreSQL — основное обязательное хранилище бизнес-данных MVP. Расширение
pgvector используется для точного cosine-поиска. PostgreSQL Full-Text Search
для лексического поиска пока не реализован. Доступ к проекту и источникам проверяется до
поиска и до передачи контекста модели. При реализации hybrid retrieval
объединение выдач, например RRF, и качество поиска проверяются на фиксированном
наборе примеров.

Импортёр из #14 переносит существующие проекты и требования с SQLite,
сохраняя контракты API и версии. Миграции схемы версионируются; наличие расширения vector
проверяется при запуске. Установка расширения требует соответствующих прав.
Перенос локальных данных предусматривает резервную копию, проверку
целостности и количества записей, безопасный отказ при ошибке и сохранение
исходной SQLite-базы.

Реализация #7 хранит в PostgreSQL фрагменты источников и embeddings BGE-M3
размерности 1024; фрагменты — до 1000 Unicode code points с перекрытием 100. Генерация
и анализ пар реализованы в #8. Семантический поиск уже работает;
FTS, hybrid retrieval и HNSW пока не реализованы. Команды запуска и импорта —
в [README](../../README.md).

## Причины и альтернативы

Единая база позволяет использовать транзакции и связи SQL для бизнес-данных
и векторов, фильтровать данные по workspace/project и уменьшить число
компонентов и проблем синхронизации.

ChromaDB и Qdrant подходят для векторного поиска, но отдельное хранилище
потребовало бы синхронизации с реляционными данными и дополнительной эксплуатации.
SQLite использовался для начальной реализации, но целевой стек MVP — PostgreSQL.

## Ограничения и пересмотр

PostgreSQL и расширение добавляют требования к локальной среде, правам,
резервному копированию и миграциям. Качество и производительность поиска зависят
от модели, данных и способа индексации; сам выбор pgvector их не гарантирует.
При подтверждённых требованиях к масштабу, задержке, качеству или эксплуатации,
которые невозможно удовлетворить измеренной конфигурацией PostgreSQL, выбор
специализированного поискового движка можно пересмотреть на основе нагрузки,
оценочного набора и стоимости сопровождения.
