# ADR-002: явный локальный генератор OpenVINO GenAI на Intel NPU

Статус: экспериментальное решение для #22, до проверки на ноутбуке.
Дата исследования: 2026-10-28. Слияние в main и аппаратная приёмка отложены.

## Контекст и решение

Целевое оборудование — Core Ultra 7 268V (Lunar Lake), 32 GB общей памяти.
Наличие `intel_vpu` и `/dev/accel/accel0` подтверждает обнаружение устройства,
но не выполнение генерации. Intel Arc/Vulkan-профиль Ollama использует GPU.

Добавляем явно выбираемый адаптер `analysis.Generator` к отдельному Python
процессу OpenVINO GenAI на Linux-хосте. Транспорт — HTTP через Unix socket,
каталог которого доступен backend. Это позволяет использовать установленные
драйверы хоста без переноса их в образ приложения и выдачи контейнеру устройств
или privileged-доступа. Python нужен только для выбранного NPU-профиля.

Устройство генерации — строго `NPU`; `AUTO`, `HETERO` и автоматического перехода
на CPU/GPU/облако нет. Токенизация и управление процессом выполняются на CPU.
Ошибки доступа, компиляции, превышения контекста и ответа завершают запрос.
Текущие проверки области доступа, источников, схемы результата и устаревания
сохраняются в приложении. Вывод модели остаётся предложением для человека.

BGE-M3 (1024 измерения) остаётся в явно настроенном локальном Ollama.
Работа BGE-M3 на NPU не подтверждена: поддержка отдельных embedding-моделей
OpenVINO не доказывает совместимость BGE-M3, pooling и текущих векторов.
Замена embedding-модели и переиндексация не входят в этот эксперимент.

## Закрепляемые зависимости

| Назначение | Версии | Происхождение / лицензия |
| --- | --- | --- |
| Runtime | `openvino==2026.4.1`, `openvino-genai==2026.4.1.0`, `openvino-tokenizers==2026.4.1.0` | OpenVINO / Intel; Apache-2.0 |
| Runtime transitive | `numpy==2.5.4`, `openvino-telemetry==2025.2.0` | NumPy (BSD-3-Clause), OpenVINO Telemetry (Apache-2.0) |
| Явная подготовка весов в отдельной среде | `nncf==2.19.0`, `onnx==1.18.0`, `optimum-intel==2.1.0`, `transformers==5.0.0` | Intel, ONNX, Hugging Face; Apache-2.0 |
| Исходные веса | `Qwen/Qwen2.5-7B-Instruct`, конкретная revision и локальный манифест файлов | Qwen; Apache-2.0 |

Тройка runtime соответствует официальной [матрице ABI](https://docs.openvino.ai/2026/get-started/install-openvino/configurations/genai-dependencies.html).
Версии инструментов экспорта взяты из [NPU guide](https://docs.openvino.ai/2026/openvino-workflow-generative/inference-with-genai/inference-with-genai-on-npu.html),
а не из произвольных последних пакетов. Эти инструменты и их существенные
зависимости (PyTorch, NumPy, Hugging Face Hub, Safetensors, Tokenizers) не должны
попадать в runtime-среду только ради экспорта. Нужно сохранить фактически
разрешённые зависимости и отчёт установки на ноутбуке; указанные верхнеуровневые
pins не являются полным транзитивным lock-файлом.

OpenVINO — активно сопровождаемый Intel-проект с документацией и отдельными
GenAI-релизами; Optimum Intel — официальный адаптер Hugging Face. Проверены
метаданные происхождения и лицензий [runtime](https://pypi.org/project/openvino/2026.4.1/),
[GenAI](https://pypi.org/project/openvino-genai/2026.4.1.0/),
[Tokenizers](https://pypi.org/project/openvino-tokenizers/2026.4.1.0/),
[NNCF](https://pypi.org/project/nncf/2.19.0/),
[ONNX](https://pypi.org/project/onnx/1.18.0/),
[Optimum Intel](https://pypi.org/project/optimum-intel/2.1.0/) и
[весов Qwen](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct).
Используем официальные пакеты и сохраняем лицензии/third-party notices.
Закреплённая тройка runtime установлена в среде разработки; импорт и наличие только CPU проверены без весов. Существенные runtime-зависимости NumPy и Telemetry закреплены по фактическому разрешению установки.
Полный аудит лицензий и уязвимостей разрешённого дерева зависимостей не запускался;
это не утверждение об отсутствии известных уязвимостей.

OpenVINO/NNCF документируют telemetry и команду `opt_in_out --opt_out`.
В среде подготовки её нужно явно отключить; runtime не должен загружать веса
или отправлять требования в сеть.

## Драйвер и подготовка модели

Кандидат для проверки Linux — официальный [Intel NPU driver v1.38.0](https://github.com/intel/linux-npu-driver/releases),
сборка `20260910-34487311128`, Level Zero `libze1` 1.32.0.
В release указан Lunar Lake, Ubuntu 24.04/26.04 и проверенная конфигурация с
OpenVINO 2026.3.1. Это не подтверждение всей комбинации с 2026.4.1 на ноутбуке;
указанное в release ядро — проверенная конфигурация, а не установленный нами минимум.
Kernel driver, firmware, userspace и права группы render проверяются отдельно.
Архив драйвера содержит подписи `.deb`; проверку выполняют по инструкции Intel.
Обновление драйверов и перезагрузка — ручные действия владельца ноутбука.

[INTEL-SA-01456](https://www.intel.com/content/www/us/en/security-center/advisory/intel-sa-01456.html)
предписывает Linux NPU driver 1.32.0 или новее. Выбранный кандидат выше этого
порога. [Релиз OpenVINO 2026.4.1](https://github.com/openvinotoolkit/openvino/releases/tag/2026.4.1)
содержит исправления обработки скомпилированных моделей и некорректных входов;
это дополнительное основание использовать patch-релиз. Чужие скомпилированные
кеши не рассматриваются как доверенные веса.

Для Qwen 7B исходный safetensors snapshot экспортируется явно с симметричной
INT4-компрессией, `--sym --weight-format int4 --ratio 1.0 --group-size -1`.
Это новые OpenVINO IR-файлы; GGUF Ollama и его digest не подменяют их происхождение.
Фиксируются revision источника, версия инструментов, параметры экспорта и hashes
всех локальных файлов, влияющих на модель и токенизацию. Запуск не скачивает веса.

## Ограничения и проверка

NPU использует собственные пределы prompt/response. Контекст Ollama 32768
не переносится автоматически. Подготовленный chat template токенизируется
без усечения; превышение настроенного бюджета возвращает ошибку. Бюджет и
версия runtime входят в происхождение профиля генератора.

Для начала используем инструкцию формата ответа в prompt и строгую проверку
JSON приложением. [Structured Output](https://openvinotoolkit.github.io/openvino.genai/docs/guides/structured-output/)
документирован на CPU; его пригодность для конкретной NPU pipeline здесь
не установлена. При некорректном JSON запрос завершается ошибкой без скрытого
исправления моделью или перехода на другой runtime.

До принятия решения нужны реальные запуски на ноутбуке: известная коллизия,
совместимая пара и недостаток данных с ожидаемыми источниками; фактическое
NPU-выполнение; первый/повторный запуск, задержка, память и prompt tokens.
Сравнение с CPU/GPU использует одинаковые примеры и явно указывает различия
квантования и весов. Ускорение и качество заранее не гарантируются.
Обычный CI проверяет проводку и ошибки детерминированными заглушками.

Альтернатива — оставить Ollama CPU/Intel Arc. Это существующий путь возврата,
который выбирают явно с сохранением БД, весов и результатов; эксперименты NPU
не требуют удаления volumes. Контейнерный NPU runtime можно рассмотреть после
подтверждения рабочей комбинации драйвера, ОС и модели на хосте.
