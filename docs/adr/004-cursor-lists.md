# ADR-004: Курсорные списки и виртуализация

Статус: принято для задачи #38.

Проекты, требования и пары анализа имеют дополнительные GraphQL connection-поля:
`projectsConnection`, `requirementsConnection`, `analysisPairsConnection`.
Старые `limit/offset`-поля сохраняются для режима «По страницам» и интеграций.
Connection возвращает `edges { cursor node }`, `pageInfo { endCursor hasNextPage }`
и `totalCount` всей доступной выборки с теми же фильтрами.

Сортировка проектов и требований — неизменяемые `created_at,id`, пар —
`position,id`. Следующая страница использует SQL keyset-условие; удаление граничной
записи не делает курсор недействительным. Курсор — версионированный непрозрачный
для клиента base64url JSON, привязанный к workspace, типу списка, проекту,
запуску и фильтрам. Он не является полномочием: доступ проверяется при каждом
запросе. Курсор не гарантирует снимок данных между отдельными HTTP-запросами;
вставки перед границей появляются после инвалидации/обновления, удаления
исчезают при следующем обновлении. Сервер ограничивает `first` диапазоном 1–100,
значение по умолчанию — 40.

Клиент запрашивает 40 записей за раз. Это ограничивает объём текста и число
запросов по сравнению с прежними страницами по 20 записей; порог предзагрузки
и виртуализация проверяются детерминированными браузерными сценариями.
Сторонние клиенты GraphQL и библиотеки виртуализации не добавляются.
Карточки измеряются `ResizeObserver`, вне окна просмотра остаются заполнители
измеренной/оценочной высоты. Фокусируемая карточка сохраняется в DOM.
Резервная кнопка «Загрузить ещё» доступна с клавиатуры; ошибка следующей порции
не удаляет ранее загруженные записи.

Последовательность страниц кешируется по идентичности списка и фильтров;
смена сессии очищает данные и отбрасывает запоздалые ответы. SSE инвалидирует
последовательность целиком: клиент повторно проходит загруженный префикс от
первого курсора, затем атомарно заменяет снимок. Это предотвращает смешивание
страниц до и после вставки, удаления или изменения статуса пары. При фоновом
запросе карточки остаются на экране. Закрытые группы не загружаются; каждая
открытая группа имеет собственную последовательность и использует прежнюю
классификацию и общие серверные счётчики.

Выбранный режим и номер обычной страницы хранятся в URL (`listMode=pages&page=2`);
Back/Forward восстанавливают их. Переход к источнику выбирает содержащую его
обычную страницу через replaceState, без дополнительного шага в истории.
Кеш и позиция бесконечного списка сохраняются при клиентской навигации в
карточку и обратно в пределах текущей сессии вкладки; полная перезагрузка
страницы начинает загрузку заново.
