# ADR-008: локальный двухэтапный анализ пар

Статус: реализация #48; аппаратная приёмка остаётся открытой.

После подготовки кандидатов один владелец запуска обслуживает две ограниченные
worker-петли: классификацию Laya и сравнение LLM. Каждая держит не более одного
вызова. LLM выбирает только пары с успешно сохранённым результатом Laya.
Уведомление после commit будит вторую петлю; завершение всей классификации не
является барьером. Все related/unrelated/uncertain направляются на итоговый
анализ. Точные текстовые дубли после классификации сохраняют детерминированный
вердикт без дополнительной генерации.

Координатор сохраняет существующие session advisory lock и lease запуска.
Блокировка запрещает конкурирующим экземплярам захватывать другие запуски,
но не сериализует два этапа внутри владельца и не охватывает поиск embeddings.
Модельные вызовы выполняются вне транзакций. Короткие транзакции проверяют права,
версии источников, профиль и fencing token до выдачи контекста и после inference.
Отмена запрещает позднюю публикацию обоих этапов; замена с ожиданием сохраняет
пригодный ответ уже выполняющейся LLM. Ошибка этапа затрагивает только его пару;
повтор использует сохранённую классификацию. После рестарта прерванный запуск
требует явного retry, как ранее. Exactly-once inference до commit не обещается.

Миграция 011 хранит отдельные статус, JSON результата и время Laya. Профиль
сравнения включает профили обоих адаптеров, инструкции и параметры. Кеш
переиспользует оба результата вместе только при точном совпадении источников и
профиля. Старые запуски не получают выдуманных оценок. Без явно заданной модели
Laya сохраняется прежний одноэтапный режим, что позволяет обновить приложение
без скачивания новой модели и миграции результатов.

Каждый переход этапа увеличивает ревизию запуска в той же транзакции, что и
результат. SSE отдаёт агрегаты двух этапов без текстов и оценок; подробности пары
читаются GraphQL по запросу. Права и reset/reconnect остаются общими с ADR-006.

Embedding-очередь имеет локальный admission gate: до восьми интерактивных
запросов, один вызов embeddings одновременно, приоритет поиска перед фоновой
индексацией и фоновый слот после четырёх поисковых вызовов. Отмена освобождает
ожидающего. SQL lease/advisory fencing индекса сохраняется. Это гарантия одного
процесса, не распределённый scheduler: несколько backend и общий GPU не получают
глобального приоритета или гарантированного latency из этой настройки.

URL трёх ролей задаются независимо; разрешены loopback и фиксированные имена
Compose-сервисов. NPU остаётся отдельным генератором, облачного fallback нет.
Число загруженных моделей Ollama настраивается явно. Две Go-петли не доказывают
одновременный inference на физическом устройстве: требуются opt-in замеры.

Ограничения Laya и настройка описаны в [инструкции](../laya-pipeline.md).
