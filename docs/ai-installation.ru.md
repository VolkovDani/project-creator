# Установка Project Creator с помощью AI-ассистента

[English version](ai-installation.md)

Используйте эту инструкцию, когда AI-ассистент помогает человеку установить
приложение Project Creator и его среду локальных моделей. Сначала ассистенту следует прочитать
README и инструкцию настройки из выбранной пользователем копии репозитория,
затем определить ОС и архитектуру перед рекомендацией команд. Нельзя считать,
что другая копия или сохранённые ранее инструкции соответствуют файлам на
компьютере пользователя. Сейчас поддерживаются нативный Linux x86_64, Python 3
для CLI и Docker Engine с Compose v2.20+. Windows, macOS, ARM и Docker Desktop
не входят в матрицу поддержки CLI. Для NPU дополнительно нужны Python 3.12 и uv
версии 0.12.13 или новее. Инструкция описывает CLI установки. После установки можно
[подключить внешнего ассистента через MCP](mcp-integration.ru.md).

## 1. Определите оборудование и выберите профиль

Перед настройкой проверьте устройство и prerequisites:

```bash
uname -s
uname -m
python3 --version
docker info
docker compose version
```

Для наиболее универсальной локальной настройки выберите `cpu`. Профили `arc`,
`nvidia`, `amd` и `amd-vulkan` используйте после установки и проверки
соответствующего системного драйвера и поддержки контейнеров. CLI не устанавливает
системные драйверы. Для NPU сначала выполните требования из
[инструкции CLI](setup-cli.md#системные-prerequisites) и
[инструкции Intel NPU](intel-npu.md). В инструкции устройства приведены текущие
ресурсные бюджеты и аппаратные ограничения; обнаружение устройства само по себе
не подтверждает, что генерация будет на нём работать.

## 2. Сохраните существующую установку

Если репозиторий уже установлен, запускайте настройку из той же директории,
с прежним `.env` и точным именем Compose-проекта. Если раньше запускали
`docker compose -p`, укажите это имя при первом запуске CLI. Другое имя создаёт
отдельное пространство имён томов Docker.

CLI сохраняет существующие секреты, настройки, тома базы данных и веса моделей.
При повторном запуске и диагностике не удаляйте `.env`, `.project-creator/`,
`.npu/` или тома Docker. CLI не выполняет `down --volumes` и не переносит данные
между именами проектов. Перед переключением профиля прочтите раздел
[о существующей установке и сохранении данных](setup-cli.md#существующая-установка-и-сохранение-данных).

## 3. Настройте и запустите

Из корня репозитория явно выберите локальное устройство для inference. Например:

```bash
./project-creator setup --device cpu
```

Другие профили: `arc`, `nvidia`, `amd`, `amd-vulkan` и `npu`; поддерживаемые
комбинации NPU + Arc и выбор адаптера описаны в инструкции CLI. `setup` явно
загружает локальные веса и контейнеры, запускает выбранный runtime и проверяет
приложение вместе с реальным AI-сценарием. Перед запуском проверьте загрузки
моделей и контейнеров. Для последующего запуска можно использовать:

```bash
./project-creator up
./project-creator doctor
```

`doctor` проверяет окружение, доступность UI/API и закреплённые модели; inference
он не запускает. `up` повторно выполняет AI-сценарии. Чтобы остановить среду с
сохранением данных, выполните:

```bash
./project-creator down
```

## 4. Проверьте inference, а не только контейнеры

Успешный запуск контейнеров или healthcheck не доказывает, что выбранная модель
выполнила inference. Убедитесь, что `setup` или `up` успешно завершила
синтетические сценарии embeddings и генерации. Для GPU-профиля проверьте
указанную модель и положительное измерение VRAM offload: оно подтверждает offload,
но не доказывает, что все операции выполнялись на GPU. Ограничения зависят от
профиля и модели.

Если настройка завершилась ошибкой, соберите диагностику:

```bash
./project-creator doctor
docker compose ps
docker compose logs --tail=100 backend frontend ollama
```

Сохраняйте отчёты в исключённом из Git корневом каталоге `logs/`; отчёты NPU
runtime и установки находятся в `logs/npu/`. Например:

```bash
mkdir -p logs
docker compose logs --no-color > logs/compose.log
```

Не публикуйте `.env`, логи и отчёты установки: они могут содержать локальные
пути, сведения об оборудовании или контекст эксплуатации. Перед передачей
диагностики удалите конфиденциальные данные. Не вставляйте секреты в ассистента
или задачу.

## Разрешения и расходы

`setup` — явная команда, загружающая веса моделей, контейнеры и зависимости
выбранного профиля. Сначала проверьте загрузки и свободное место. Не выполняйте
разрушающую очистку, например `docker compose down --volumes`, удаление данных
проекта или изменение рабочей установки без согласия владельца на конкретную
операцию и наличия резервной копии. Изменение системных драйверов, действия с
повышенными правами и перезагрузка выполняются отдельно.

Описанный запуск использует локальные модели. Любая облачная интеграция
должна быть настроена явно; до передачи контекста проекта требуется согласие.
Сбой локального inference не должен незаметно переключать обработку в облако.
Платные облачные сервисы или подписки требуют отдельного согласования; эта
инструкция их не включает.

Точные prerequisites, выбор устройства, восстановление и коды ошибок приведены
в [полной инструкции CLI](setup-cli.md).
