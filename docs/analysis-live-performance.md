# Замеры live-анализа #47

Дата: 5 ноября 2026 года. До: `d5e1bb2`; после: реализация `37df41a`.
Это воспроизводимый браузерный сценарий с заглушками GraphQL/SSE, а не замер
настоящей LLM или повтор исходных скриншотов с 206 МБ трафика.

## Методика

Linux x86_64, Node 24.21.0, Next.js 16.4.3, React 19.2.0,
Playwright 1.56.1, Chrome for Testing 151.0.7922.34. Production проверяется через
`next build` / `next start`, dev — отдельно через `next dev` со StrictMode.

Фикстура содержит 20 пар. Двадцать конечных SSE-потоков последовательно переводят
по одной паре из pending в collision; браузер переподключается с Last-Event-ID.
В конце каждый прогон проверяет в UI «Обработано 20 из 20». Ответы GraphQL
проецируются по AST фактически выбранных полей, включая fragments, и учитывают
фильтры/пагинацию. Замер не отправляет данные внешним провайдерам и не требует БД.

Считаются тела запросов и ответов GraphQL, тела SSE, операции, одновременно
выполняемые запросы, число переданных строк и повторные источники сводки.
HTTP-заголовки, TLS, gzip, статические ресурсы и dev HMR не включены в байты API.
Это **body bytes**, не DevTools `Transferred`. Задержки зависят от компиляции,
планирования браузера и заданного reconnect, а не от скорости генерации модели.

До изменения группы раскрыты по умолчанию. После отдельно проверены новый
компактный экран с закрытыми группами и раскрытие всех шести групп. В последнем
случае карточки подробностей и происхождение не раскрываются автоматически.
Загрузка и повторное использование их кеша проверены отдельными Playwright-тестами.

Повторная передача неизменившегося `sources` в сводке до изменения —
225 606 B; после — 0. В раскрытых группах до и после передано 400 строк
в production и 380 в dev для 20 уникальных ID. Это 380/360 повторов
**идентификаторов**, не доказательство неизменности результата: статус пары
меняется. После повторяются компактные записи, без `text` и `explanation`.

Первый положительный прогресс появился через 1,137 с до и 1,585/1,090 с после
в production (закрытые/раскрытые группы). В dev — 2,747 с до и 2,471/2,241 с после.
Двадцатое событие пришло через 10,684 с до и 10,943/10,590 с после в production;
11,974 с до и 11,418/11,174 с после в dev. Время появления финального UI отдельно
не профилировалось: проверяется его достижение после события.

Максимальное число всех одновременно наблюдавшихся сетевых запросов, включая
загрузку ресурсов, — 10 в production и 18 в dev как до, так и после. Для нагрузки
GraphQL используется отдельная колонка in-flight; неограниченная очередь
`pending` в этих прогонах не наблюдалась.

## Воспроизведение

Из корня, после `npm ci` в `frontend/` и установки браузера Playwright:

```bash
node scripts/analysis-live-benchmark.mjs --root=. --transport=push --mode=both --output=logs/issue-47/after
node scripts/analysis-live-benchmark.mjs --root=. --transport=push --mode=both --expand-groups --skip-build --output=logs/issue-47/after-expanded
```

При необходимости задайте `E2E_CHROMIUM_PATH` либо `--chromium=/path/to/chrome`.
`--skip-build` допустим только для уже собранного актуального production-кода.
Не запускайте сборку одновременно с тестовым сервером из той же директории.

Для baseline подготовьте отдельный checkout или архив `d5e1bb2` с установленными
зависимостями в его `frontend/` и передайте его абсолютный путь через `--root`:

```bash
node scripts/analysis-live-benchmark.mjs --root=/path/to/baseline --transport=invalidate --mode=both --output=logs/issue-47/before
```

В старом checkout запускается текущий скрипт из основной рабочей директории:
он содержит общий инструмент подсчёта. Для dev Turbopack зависимости должны
находиться внутри checkout, а не указывать symlink за пределы его root.

Сырые диагностические отчёты игнорируются Git и остаются в `logs/issue-47/`:
`baseline-remeasured/baseline.json`, `after-default-final/baseline.json` (production),
`after-default-dev-final/baseline.json` (dev), `after-expanded-final/baseline.json`.
Более ранние пробы не использованы в этой таблице.

## Проверки и границы

Пройдены Go-тесты с отдельной PostgreSQL/pgvector БД, `go vet`, Go/TS codegen
без повторных изменений, frontend unit-тесты, Biome, typecheck и production build.
Пройдены 68 UX-тестов на production-сборке и 3 E2E-теста с настоящими Go API/БД,
включая две вкладки. Проверяются lazy-детали и происхождение, кеш при повторном
раскрытии, медленный старый snapshot, дубли/старые ревизии, reset, retry, отмена,
сохранение форм/фокуса и очистка при отзыве доступа. Серверные тесты проверяют
согласованность SSE/GraphQL, ревизию без heartbeat-событий, границы workspace
и порядок/replay событий нескольких проектов.

Замер не определяет предельное число подписчиков или нагрузку SQL для огромной
очереди. Открытые группы всё ещё перечитывают компактный загруженный префикс;
материализация счётчиков и передача дельт состава списков могут дополнительно
уменьшить эту работу. Настоящая LLM, оборудование, gzip и исходный пользовательский
набор не измерялись. #39 не реализуется этой задачей.
