# Проверка классификации требований

[English version](classification-review.md)

Откройте **Классификацию** в меню проекта или разверните **Классификацию** в карточке требования. Прочитайте исходный текст и проверьте **Смысл** и **Форму** по отдельности. В справочнике классов есть отличительные признаки, примеры и контрпримеры для обеих осей.

Нажмите **Проверить классификацию**, выберите значения обеих осей и нажмите **Сохранить классификацию**. Для любой оси можно оставить **Не определено**. Закрытие диалога отменяет несохранённый выбор. Если во время редактирования изменился текст или решение, прочитайте актуальный текст перед применением меток к новой версии. В карточке видна версия текста, к которой относилось прежнее решение.

## Предложения модели и решения пользователя

В карточке видны действующее решение, его статус, источник и сохранённое имя модели. Раскройте альтернативы, чтобы увидеть до трёх вариантов с наивысшими оценками в каждой группе и их некалиброванные модельные оценки. В сведениях о решении доступны сохранённые данные о модели и версии вопроса. Модель, настроенная на ручную проверку предложений, может оставить обе оси неопределёнными и вернуть альтернативы. Проверка может потребоваться и без альтернатив, например при превышении входного лимита модели.

Явный повторный анализ подтверждённой записи сохраняет решение пользователя. В **Истории решений** можно сравнить новые предложения модели с прежними решениями, увидеть версию исходного текста и ревизию решения. Чтобы увидеть следующие 10 решений, прокрутите историю до конца или нажмите **Загрузить ещё**. При отключённой автоматической классификации доступны ручная проверка и история.

## Объяснение классификации

Откройте раздел **Независимая оценка ИИ** в карточке классификации. Он появляется, когда классификатор сохранил предложенную метку или ранжированные варианты для текущей версии текста. Если затем пользователь подтвердил или исправил классификацию, раздел остаётся доступным. Одного ручного решения, задания в очереди, ошибки проверки или проверки без меток и вариантов для этого недостаточно.

В полях **Целевой смысл** и **Целевая форма** выберите категории по отдельности, затем нажмите **Объяснить классификацию**. Можно выбрать категории, отличные от сохранённых меток. Сервер дважды последовательно вызывает локальную модель и показывает обе оценки в карточке. Каждый вызов получает полный исходный текст, критерии выбранной категории и сохранённые метки своей оси. Ранжированные варианты доступны в карточке классификации. Для найденного признака модель выбирает по номеру фрагмент текущей версии требования. Сервер показывает его дословно, чтобы вы могли проверить, подтверждает ли он вывод модели. Например, для пользовательской истории она проверяет роль, действие и ценность. Условия приёмки для этой формы необязательны. Результат может содержать уточняющие вопросы, вариант формулировки и ограничения оценки. Чтобы использовать формулировку, скопируйте её в редактор требования, проверьте и сохраните правку самостоятельно. Запрос объяснения сохраняет исходный текст и классификацию без изменений.

Запрос можно отменить. Сервер ждёт обе оценки до трёх минут. Если изменились текст, решение или предложение модели, проверьте актуальную карточку перед повторным запросом. После правки текста классификатор сначала должен предложить метку или варианты для новой версии. Если модель занята, повторите запрос позже.

Проверенные оценки смысла и формы кешируются в PostgreSQL по отдельности. При смене цели по одной оси сервер повторно использует подходящую оценку другой оси. Учитываются рабочая область, требование, версии текста и решений, выбранная категория по этой оси, язык, версия справочника и профиль модели. Записи переживают перезапуск и по умолчанию хранятся без срока истечения. Через CLI можно очистить одну ось, обе оси классификации или все зарегистрированные разделы кеша ИИ. [Управление кешем](setup-cli.md#очистка-кеша-ии)

Текст оценки следует выбранному языку интерфейса и может содержать технические обозначения на латинице. Если в ответе NPU появилась буква из неподдерживаемой письменности, сервер может один раз повторить запрос по этой оси с более строгим набором допустимых символов. Если ответ исчерпал лимит токенов, повторный запрос может вернуть сокращённую оценку с цитатами. Фрагменты требования цитируются дословно с сохранением исходной письменности.

Сервер использует настроенный локальный генератор выжимок Ollama с закреплённым дайджестом модели. Если такой генератор не настроен, сервер использует локальный генератор общего назначения Ollama с закреплённым дайджестом или закреплённый профиль OpenVINO NPU, выбранный для генерации через локальный Models Configurator. На NPU оценка использует тот же локальный профиль, что и общая генерация. Сервер передаёт каждый запрос целиком в Models Configurator для подсчёта токенов и применяет точный входной лимит активного профиля. Профиль также задаёт лимит ответа. В старых версиях менеджера без подсчёта токенов лимиты применяются во время генерации. У пользовательской истории NPU проверяет роль, действие и пользу. Карточка сообщает о недоступности модели, превышении допустимого размера запроса, отклонении ответа, истечении времени ожидания, отмене и сбое запроса к серверу. После сбоя по одной оси сервер может повторно использовать проверенную оценку другой, если исходные данные всё ещё актуальны. Исходный текст обрабатывается локально на протяжении всего запроса. [Настройка Models Configurator](adr/012-standalone-model-manager.ru.md#подключение-установки-compose)

## Очереди проверки

В разделе классификации проекта записи можно отбирать по смыслу, форме и статусу. Кнопка **Требуют проверки** открывает соответствующую очередь. Счётчики групп относятся ко всему проекту. При выборе группы применяется фильтр. Чтобы увидеть следующие 20 записей, прокрутите список до конца или нажмите **Загрузить ещё**. При изменении классификации обновляются отдельные видимые карточки и общие счётчики.

Кнопка **Классифицировать необработанные записи** ставит существующие записи в очередь. Кнопка **Повторить неудачные классификации** запускает повтор для записей с ошибкой. На панели показано, сколько записей в очереди, в работе и с ошибками. В карточке на этой странице можно запросить классификацию или повторить попытку для одной записи. Чтобы подтвердить несколько сохранённых предложений модели, отметьте их среди загруженных записей и нажмите **Подтвердить выбранные**. Флажок доступен для актуального предложения с определёнными смыслом и формой. Если модель вернула альтернативы для ручной проверки или одна из осей не определена, решение принимается отдельно. При загрузке следующих записей отметки сохраняются. Смена фильтров снимает отметки. Перед сохранением каждой записи приложение сверяет выбранные метки, версию текста и ревизию решения. В результате перечислены подтверждённые и изменившиеся записи, а также ошибки сохранения.
