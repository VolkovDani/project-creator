# Языки документации

[English version](README.md)

Все новые документы и изменения документации требуют английской и русской
версий с одинаковыми требованиями, командами, ограничениями и статусами проверки.
Проверяйте обе версии в одном PR. Добавляйте взаимные ссылки.

Новые документы: `<name>.md` для английского и `<name>.ru.md` для русского.
Существующие русские канонические файлы сохраняют пути, английский перевод
получает имя `<name>.en.md`. Не меняйте обнаруживаемые инструментами имена,
например `AGENTS.md`. Старые непереведённые документы — явный пробел, а не
подтверждение двуязычного покрытия. Переводите их при обновлении; сохраняйте
даты и SHA исторических отчётов.

## Добавление другого языка

1. Выберите языковой тег, например `de` или `pt-BR`, и создайте каталог
   `docs/i18n/<language-tag>/`.
2. Повторите путь оригинала относительно корня репозитория. Например, немецкий
   перевод `docs/release-acceptance.md` располагается по пути
   `docs/i18n/de/docs/release-acceptance.md`.
3. Добавьте индекс языка со ссылками на переводы, оригиналы и английскую и
   русскую инструкции о языках. Отметьте отсутствующие переводы.
4. Переводите текст, сохраняя команды, переменные окружения, идентификаторы,
   ключи API, пути и имена моделей. Не включайте настоящие секреты и данные клиентов.
5. Проверьте относительные ссылки из фактического каталога перевода. Сверьте
   команды, предупреждения, критерии приёмки и статус выпуска с обеими базовыми
   версиями. При изменении поведения обновляйте все имеющиеся языковые варианты;
   не оставляйте незаметно устаревшие инструкции.

Для перевода не нужны искусственные тесты; выполните `git diff --check` и
проверьте пути ссылок. Изменение поведения требует обычных проверок проекта.
