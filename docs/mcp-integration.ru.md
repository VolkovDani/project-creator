# Предложение по интеграции MCP

[English version](mcp-integration.md)

Этот документ фиксирует **предложение**, а не реализованное поведение и не
утверждённое обязательство. Существующее приложение остаётся источником истины
для проектов, требований, документов-источников и их версий. Внешний
ассистент мог бы подключаться через Model Context Protocol (MCP) как
необязательный адаптер к существующей бизнес-логике. Задача:
[Issue #146](https://github.com/VolkovDani/project-creator/issues/146).

## Предлагаемый объём

Адаптер MCP вызывал бы доменные сервисы приложения, не обращаясь к хранилищу
напрямую, не дублируя бизнес-правила и не создавая вторую доменную модель.
Некоторых описанных возможностей — в частности, сохранения предложений с
происхождением источников — пока нет; для них потребуется отдельно спроектировать
доменный сервис и API приложения. Начальное направление предлагается ограничить
следующим:

- Читать требования и исходные материалы только в разрешённой вызывающему
  области проекта и клиента.
- Передавать идентификаторы и версии источников, а также сведения об их
  актуальности, чтобы внешний ассистент сам выполнял анализ.
- Сохранять предложение ассистента с указанными версиями источников,
  происхождением, ограничениями и статусом. Сохранение предложения не делает
  его подтверждённым фактом.
- Не предоставлять через предлагаемую интеграцию изменение исходных требований
  или статуса их согласования. Человек по-прежнему проверяет и применяет
  изменения через приложение.
- Показывать, что источники изменились, удалены или недоступны, и помечать
  сохранённое предложение как устаревшее или с недоступными основаниями;
  не выдавать старый анализ за актуальный.

Права доступа необходимо проверять до получения контекста и передачи его
ассистенту, а перед записью предложения — повторно. Адаптер не должен
допускать доступ к данным другого клиента. Передача контекста облачной модели
требует явной настройки и согласия пользователя. Сбой локальной модели не
должен автоматически переключать обработку на облако.

## Пока не решено

Выбор SDK MCP, транспорта (например, stdio или HTTP), механизма аутентификации,
размещения, сопоставления разрешений и точного набора операций чтения и записи
остаётся открытым. Для этого нужны отдельная задача реализации и проектное
обсуждение. Предложение не выбирает SDK, не добавляет зависимость, не обещает
срок выпуска и не разрешает реализацию. Обсуждение ведётся в
[Issue #146](https://github.com/VolkovDani/project-creator/issues/146).

## Текущая настройка AI

В репозитории уже есть запуск локальных моделей через CLI `project-creator`.
Инструкция по [установке AI](ai-installation.ru.md) описывает определение
оборудования, настройку, проверку, диагностику и сохранение данных. Текущий
CLI управляет локальной средой приложения; MCP в нём не реализован.
