# Проверки выжимок и конвейера #48 / #72

Проверено 6 ноября 2026 года на Intel Core Ultra 7 268V, 32 GB общей памяти,
Intel Graphics (LNL) и Intel NPU. Использованы только синтетические данные
и отдельная PostgreSQL/pgvector БД. Рабочие проекты не изменялись.
Это результаты конкретных сценариев, а не оценка вероятности правильности модели.

## Конфигурация

- Ollama 0.40.11; Laya `laya:322m-multilingual-bf16`, digest
  `c1242e4a83f0e1cb58f0f191a65bbc5d3306fae274d152b8229ec574999d465d`.
- Embeddings `bge-m3:567m`, digest
  `7907646426070047a77226ac3e684fbbe8410524f7b4a74d02837e43f2146bab`.
- Выжимки: `qwen2.5:7b`, digest
  `845dbda0ea48ed749caafd9e6037047aa19acfcfd82e704d7ca97d631a0b697e`;
  отдельный явно выбранный CPU Ollama. Профиль инструкции/схемы:
  `57d2bd2b1b04e5c95717c78ed67e33bcbf7168fa62897904eb6c889fb5ee7f5a`.
- Финальное сравнение: отдельный OpenVINO NPU runtime, manifest profile
  `f36b13cbad8752f05d141eba6f817045986a615d13ffb5688fe417faeebca271`.
- Для Arc использован отдельный временный контейнер существующего Intel-образа;
  установленный том весов подключён только для чтения. Vulkan ID `0`,
  `OLLAMA_IGPU_ENABLE=1`, `OLLAMA_MAX_LOADED_MODELS=2`.

Базовый Intel-профиль обнаружил регрессию: пустой `GGML_VK_VISIBLE_DEVICES`
скрывал Vulkan-устройства. После выбора `0` и разрешения iGPU журнал подтвердил
Intel Graphics (LNL), а `/api/ps` показал одновременный GPU offload Laya
(820877720 байт) и BGE-M3 (689187061 байт). Одного успешного healthcheck
для этого вывода недостаточно.

## 21 пара и интерактивный поиск

Семь фиксированных требований дают 21 пару в режиме `all`.
Для этого измерения выжимки создаёт детерминированный адаптер; проверка
реального генератора выжимок приведена отдельно ниже. Настоящие модели
использованы для Laya, финального NPU-сравнения и embeddings-поиска.

| Сценарий | Результат | Время конвейера | Поиск во время анализа |
| --- | --- | --- | --- |
| CPU Ollama + NPU | 21/21 завершены, ошибок нет, вызовы перекрываются | около 210 с | 46 мс, 5 результатов |
| Первый прогон Arc Ollama + NPU | 21/21 завершены, ошибок нет, вызовы перекрываются | около 188 с | 826 мс, 5 результатов |
| Повторный Arc + NPU, 10 поисков | 21/21 завершены, ошибок нет, вызовы перекрываются | около 164 с | 34–68 мс; p50 50 мс, p95 68 мс |

Десять поисков начинались во время выполняющегося анализа; каждый вернул
пять результатов. Для повторного прогона измеренные p50/p95:

- До входа в embedding-провайдер: 0/1 мс. Сюда входит проверка и ожидание;
  это не отдельный production-счётчик глубины очереди.
- Сам embedding-провайдер: 48/67 мс.
- Остаток поиска после embeddings: 1/2 мс, включая SQL, разбор и возврат данных.
  Это не отдельный span исключительно исполнения SQL.

Процентили описывают только десять запросов, не задают SLA. Повторный прогон
использовал уже загруженные модели; NPU не переустанавливался между прогонами.
По наблюдениям `/api/ps` обе Arc-модели оставались загруженными одновременно.
В окне 180 замеров доступная RAM не опускалась ниже примерно 8.5 GiB.
Наблюдаемый максимум `docker stats` для исправленного Arc-контейнера — 401 MiB;
эта величина не включает всю общую GPU/NPU-память и не является стоимостью
всех моделей. Контейнер не получил `OOMKilled`. Долгая непрерывная нагрузка
и другие размеры проектов этими сценариями не проверены.

## Реальные выжимки → Laya → полные оригиналы на NPU

Отдельный тест использует три русских требования длиннее 350 и короче 800
UTF-8 байт с повторяющимся справочным контекстом: только карта, только наличные
и SMS при отгрузке. Настоящий локальный Qwen автоматически создал выжимки
текущих версий; проверены размер, исключительные разрешения, запреты и SMS.
Затем Laya получила выжимки, а NPU — точные полные оригиналы и сохранённую
подсказку Laya. Все три пары завершились; карта/наличные дали ожидаемый
`collision` с версиями исходников 1. Весь сценарий занял около 79 секунд.

Это подтверждает сквозной сценарий, но не универсальную точность сжатия.
Профиль NPU по-прежнему ограничивает полный токенизированный prompt;
возможность сравнить любые два оригинала по 10000 символов не обещается.
Превышение контекста не разрешает скрыто обрезать текст.

## Строгий оценочный набор модели

Фикстуры: `internal/analysis/testdata/summary-quality.json`.
На окончательной инструкции два обычных длинных RU/EN примера с повторяющимся
контекстом прошли строгие проверки: сохранены роль, исключительное разрешение,
запрет и срок. Два более плотных текста с несколькими условиями/исключениями
и пример с 90 обязательными идентификаторами не прошли строгий quality smoke.
В этих трёх случаях провайдер вернул явную ошибку валидации после ограниченных
попыток; некорректные выжимки не опубликованы как готовые.

Следовательно, **полный пятипримерный quality smoke не зелёный**. Пригодность
Qwen для произвольных сложных требований не подтверждена. Приложение сохраняет
оригинал, показывает ошибку и разрешает явный retry. Использование другой
модели возможно только через явную конфигурацию и новую проверку качества.
Лексические проверки также могут отвергать допустимые переформулировки;
они служат сигналом для ручного разбора, а не семантическим доказательством.

В раннем варианте схемы поле отказа генерировалось раньше текста. Вариант v2
использует `summary` перед `unsummarizable`; это устранило массовые ранние отказы
на простых примерах. Порядок JSON Schema сам по себе не гарантируется:
[описание проблемы в Ollama](https://github.com/ollama/ollama/issues/18717).
Изменение схемы не отменяет ограничения качества выше.

## Воспроизведение

Все аппаратные тесты выключены в обычном CI. Нужны отдельная
`TEST_DATABASE_URL`, свободный NPU runtime и явные полные pins:

```sh
# Переменные PIPELINE_SMOKE_* и PROJECT_CREATOR_NPU_* выбирают локальные
# runtime/model/digest; требования к ним перечислены в соответствующем тесте.
PIPELINE_SMOKE_REQUIREMENTS=7 PIPELINE_SMOKE_SEARCHES=10 \
  go test ./internal/summary -run '^TestRealNPUAndLayaPipelineWithConcurrentSearch$' -count=1 -v -timeout=9m

# Дополнительно SUMMARY_PIPELINE_SMOKE_URL/MODEL/DIGEST для генератора выжимок.
go test ./internal/summary -run '^TestRealSummaryLayaNPUFullSourcePipeline$' -count=1 -v -timeout=10m

# Отдельная оценка качества: SUMMARY_SMOKE_URL/MODEL/DIGEST.
# На проверенном Qwen пятипримерный набор имеет описанные выше ограничения.
go test ./internal/analysis -run '^TestSummaryQualitySmoke$' -count=1 -v -timeout=8m
```

Полные локальные журналы: `logs/issue-48-summary/`, исключённые из Git и
Docker build context. Там сохранены исходные неудачные проверки, исправленные
прогоны, интервалы вызовов, pins и наблюдения памяти. Нельзя запускать аппаратный
сценарий на runtime, занятом рабочим анализом: первоначальные попытки именно
поэтому получили отказ. Рабочий анализ был отменён самим владельцем перед
итоговыми проверками.
